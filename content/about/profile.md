## 我是谁

我是 **应知序**，一个目前不上班、专职跟 AI 协作做东西的独立开发者。

以前学自动化，围着煤炭、钢铁、运筹学和控制论转。读研时开始认真写代码，毕业后在能源/自动化行业待了几年，发现自己真正喜欢的不是「优化产线」，而是「把脑子里的东西做出来」。

后来大模型来了。我很快意识到：初级程序员的熟练度和手速正在贬值。怎么卷都卷不过模型，于是转向另一件事——**怎么跟 AI 更好协作、做出东西**。

## 我在做什么

现在主要在做 **见微 / OasisMind**：一个本地优先的 AI 数字花园和个人工作台。

它最初来自一个很具体的痛点：我收藏了太多东西，分类越拖越贵，拖到后面就彻底放弃。让 Agent 去整理很合适，但 Agent 得跟我有点一样的品味——那就要自己蒸馏自己。

于是见微慢慢长出来：博客、编辑器、Chat、Agent/Swarm、Task、Trigger、审批、QQ 网关……本质上是一个「常驻的数字主力」：提醒、收集、筛选、再交给 Agent 过滤。

我也在维护几个开源笔记和教程项目，以及在 RedNote 上分享一些做东西过程中的思考。

## 我为什么做见微

市面上已经有很多「AI 知识库」「AI 笔记」产品。我做见微不是因为他们不够好用，而是因为我想自己掌控几件事：

- **数据必须在本地**：Markdown 是事实源，SQLite 只是缓存。
- **Agent 必须是可控、可观测的系统**：我要知道它在哪一步、调了什么工具、为什么卡住。
- **收藏 ≠ 知识**：先多收，再让系统帮我筛。关键是别丢。

这个过程里我花了几个月时间，做出了很多市面上「好像已经有」的东西。但回头看，重点不是成品，而是过程中想清楚了：我到底想要什么。

## 我的技术直觉

我对 Agent 的直觉来自控制论：**可控、可观测**。

不是把模型当黑盒许愿，而是把运行看成状态机：输入 → 决策 → 工具调用 → 反馈 → 终止/重试。每一步都要有日志、有边界、有兜底。

技术选型上我偏向「能本地跑就别云上」：SQLite、Ollama、本地 Markdown、Docker。但我也不会拒绝好用的云端模型——DeepSeek、Kimi、Claude、OpenAI 都会用，只是数据和核心流程要留在本地。

## 现在关心的事

- 怎么让 Agent 更像一个「能控能观系统」，而不是黑盒。
- 本地优先的数字花园能不能真正代替我手动整理收藏。
- 独立开发者怎么靠「做东西」而不是「卷代码量」活下来。
- 小红书「荒原猎码人 Zero」的内容更新。
