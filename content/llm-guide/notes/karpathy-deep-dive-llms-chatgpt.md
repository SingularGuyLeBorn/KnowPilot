# Karpathy《Deep Dive into LLMs like ChatGPT》3.5 小时全栈科普笔记

> **原视频**：[Deep Dive into LLMs like ChatGPT](https://www.youtube.com/watch?v=7xTGNNLPyMI)（YouTube，2025-06，3:31:24，发布 10 天观看量即超 80 万，现已 834 万+）
> **主讲**：Andrej Karpathy（OpenAI 联合创始人、前特斯拉 AI 总监）
> **定位**：面向大众的 LLM 全栈科普——从数据、训练、对齐到使用心法，讲透 ChatGPT 这类产品背后的完整技术管线。
> **本文**：整合多方中文笔记与视频结构整理而成，按「预训练 → 后训练（SFT）→ 强化学习（RL）→ LLM 心理学 → 使用心法」五段展开。

---

## 0. 一句话核心命题

**LLM 本质是一个「统计模式模拟器」**：它通过海量互联网文本学习人类表达的统计规律，最终在对话中展现出类人能力。它不是魔法，也不是真正「懂」世界——它是在做**概率接龙**，只是接得足够好，看起来像懂了。

> Karpathy 的比喻：ChatGPT 的完整技术栈 = **预训练**（读课本，获取知识）+ **监督微调 SFT**（看老师例题，模仿专家）+ **强化学习 RL**（做练习题，自我试错超越专家）。

---

## 1. 引言：对话框背后发生了什么？

打开 ChatGPT，你看到的只是一个输入框，但背后是一条完整的三阶段流水线：

```
互联网文本 → 预训练 → Base Model（基座模型）
                  ↓
对话/指令数据 → 监督微调（SFT）→ 初步可用的助手
                  ↓
反馈/奖励 → 强化学习（RLHF / RLAIF）→ 对齐后的助手（ChatGPT）
```

三个阶段的「目的」截然不同：
- **预训练**：给模型「互联网上的所有知识」——代价是数千张 GPU 跑数月。
- **SFT**：给模型「助手人格」——从「补全文档」变成「回答问题」。
- **RL**：把模型从「模仿人类标注员」推向「超越人类标注员」（DeepSeek R1、o1/o3 这类 reasoning 模型的核心）。

---

## 2. 预训练（Pre-training）：互联网的「有损压缩」

### 2.1 数据收集与清洗

LLM 的第一步是「吞噬互联网」：
- **Common Crawl**：免费开源网页抓取仓库，18 年积累 2500 亿+ 网页，是 LLM 的「主粮库」。
- **FineWeb**（Hugging Face，44TB）：Common Crawl 的精选版，经过 5 层过滤：
  1. **URL 黑名单**：剔除成人内容、垃圾营销、恶意站点；
  2. **文本萃取**：剥离 HTML/CSS，只留纯净文字；
  3. **语言过滤**：只保留英文占比 >65% 的页面；
  4. **去重**：MinHash 指纹算法消除重复文本；
  5. **隐私清除**：删除电话号码、邮箱等 PII 信息。

### 2.2 Tokenization（分词）：文本 → 数字 ID

神经网络只能处理数字，所以文本要先切成小块再编号。例如 `hello world` → `hello` + 空格 + `world` → `[15496, 995]`（2 个 token）。**GPT-4 的词表共有 100,277 个 token**。可以用 [Tiktokenizer](https://tiktokenizer.vercel.app) 在线实验：输入一个句子，看每个单词/子词被映射成哪些数字 ID。

**Tokenization 解释了 LLM 的很多「怪毛病」**：
- 「Strawberry 里有几个 r？」——模型看不到字母，只看到 token；
- 9.11 vs 9.9 谁大？——分词器可能把 `9.11` 拆成了特定 token 组合，模型无法像人一样逐字符比较。

> 这不是模型笨，而是**它的感知粒度（token）与人类（字符/单词）不一致**。

### 2.3 训练目标：预测下一个 token

训练就是让神经网络学会：

$$
P(x_{t+1} \mid x_1, x_2, \ldots, x_t)
$$

即给定前文，预测下一个 token 的概率分布，然后最大化正确 token 的概率（最小化交叉熵损失 $\mathcal{L}=-\sum_y y\log\hat{y}$）。一次只预测一个 token，逐个生成。

**网络结构**：神经网络由两部分组成——**参数（权重）**（训练学到的数值）与**架构**（处理 token 的数学表达式）。初始预测是随机的，训练中每当识别出正确 token，就通过**反向传播**调整数十亿参数——增加正确预测的概率、减少错误预测的可能性，在数据集上重复数十亿次。

**Transformer / 注意力机制**：通过注意力让模型高效学习长距离依赖——比如写小说埋伏笔，伏笔和呼应可能隔着 10000 个 token，注意力机制让模型能「跨越」这段距离建立联系。

### 2.4 产物：Base Model（基座模型）

预训练收敛后得到 Base Model，关键特性是：
1. **它不是助手**：问它「2+2=？」，它不会回答「4」，而是把你的问题当作文本前缀，继续补全成类似互联网帖子的内容。
2. **它是随机系统**：相同输入每次输出不同（采样概率）。
3. **知识是「模糊的记忆」**：405B 参数可以看作**互联网文本的有损压缩**。高频信息记得牢，训练截止日期之后的事件会「幻觉」。
4. **高级自动完成系统**：可以逐字背诵训练数据，通过**上下文学习（in-context learning）**在提示中给示例即可引导行为——但指令遵循能力有限，尚不可用。

### 2.5 模型规模演进（视频中演示）

| 模型 | 年份 | 参数量 | 训练 token 数 |
|---|---|---|---|
| GPT-2 | 2019 | 1.6B | 约 1000 亿 |
| Llama 3 | 2024 | 405B | 15 万亿 |

视频中还演示了在 8×H100 上 4 小时、约 100 美元训练一个「迷你 ChatGPT」（nanochat），12 小时即可超过 GPT-2 的 CORE 指标；扩展到约 1000 美元（41.6 小时），模型能在 MMLU 拿 40+ 分、GSM8K 拿 20+ 分。

## 3. 后训练（Post-training / SFT）：从「模拟器」到「助手」

### 3.1 做法：换数据，继续同样的训练

把互联网数据集「扔掉」，换成**对话数据集**（user/assistant 多轮对话），用与预训练**完全相同的 next-token prediction 算法**继续训练几个 epoch。朴素但有效。

> 因为模型是神经网络，不能像传统软件那样被显式编程——只能通过「在结构化的期望交互示例上训练」来隐式「编程」它。

训练样本示例（Karpathy 给的最小对话例子）：
- **数学推理**：问「What is 2+2?」答「2+2=4」；追问「如果是 * 呢？」答「2*2=4」——教会多轮上下文。
- **人格化**：用户心情低落，助手用温暖语气安慰——教会「性格」。

### 3.2 关键机制：特殊 token

训练后引入预训练期间没用过的**特殊 token**（如 `<user>`、`<assistant>`、`<end>`），用来标记用户输入起止、AI 回复起止，让模型区分「提示」和「回复」。

### 3.3 一个深刻洞察

> **当你和 ChatGPT 对话时，你并不是在和全知的硅基生命说话——你是在和一个「被 helpful / truthful / harmless 规范训练出来的人类标注员的统计性回声」说话。**

- 早期（InstructGPT，2022）：OpenAI 雇约 40 名承包商写「提示 + 理想回答」，并遵循安全指南。
- 现代：大量用**合成数据 + 人工审查编辑**（如 UltraChat 百万级合成对话）。
- 领域特定微调：把模型适配到医学、法律、编程等专业领域。

### 3.4 幻觉的缓解（后训练阶段）

1. **说「我不知道」**：探测知识边界，加入「我不知道 / 我不确定，能提供更多背景吗？」样本。可**自动化**：用另一个 AI 模型生成问题来探测知识缺口，若答错就补一条「不确定」训练样本。若模型在训练中多次见过某问题，会给正确答案很高概率；没见过的，概率分布均匀、输出随机化——显式微调即训练模型处理这种低置信度输出。
2. **工具使用**：教模型在不确定时调用搜索（`<search_start>...</search_end>`），搜索结果注入上下文窗口，成为模型的工作记忆。

## 4. 强化学习（RL / RLHF）：从「模仿」到「超越」

SFT 只是模仿标注员；要解决复杂数学/代码题，需要**自我试错**。

### 4.1 RLHF 三步走（InstructGPT 范式）

1. **收集人类偏好数据**：同一问题生成多个答案，人类标注员排序优劣；
2. **训练奖励模型（Reward Model）**：学习「人类会喜欢哪个回答」，成为一个评分器；
3. **用奖励模型优化原模型**：模型生成答案 → 奖励模型打分 → 强化学习更新参数，让模型学会生成高分答案。

### 4.2 RL 的两种奖励来源

- **可验证的客观标准**：数学、代码题——对错一目了然，最可靠；
- **人类偏好模型**：写段子/写诗是否「搞笑优美」——需要 reward model 近似。

### 4.3 推理模型的「涌现」

DeepSeek R1、OpenAI o1/o3 这类**推理模型**，就是让模型面对复杂题自我尝试、答对给奖励、答错不给，在成千上万次试错中**自己发现「思维链」（Chain of Thought）策略**。

最有趣的现象：模型会开始「自言自语」——「等等，这里好像算错了，我重新检查一下」。这种「思考」不是人类教的，而是它在 RL 中**为了拿到正确答案涌现出来的**。

**两类模型的分野**：
- **SFT 模型**（如 GPT-4o）：反应快，靠「直觉」，适合事实性问题；
- **推理模型**（如 o1、DeepSeek R1）：反应慢，通过输出大量 token「思考」，适合复杂逻辑问题。

## 5. LLM 的「心理学」与使用心法

Karpathy 用几个思维模型帮你建立直觉，避免踩坑：

### 5.1 参数 = 模糊记忆；上下文 = 工作记忆

| | 参数（Weights） | 上下文窗口（Context Window） |
|---|---|---|
| 类比 | 一个月前读过的书 | 摊在桌子上的书 |
| 特性 | 长期但模糊、有损、不可检索 | 精确、可随时引用 |
| 存取 | 训练时写入 | 推理时可用 |

> **应用技巧**：让模型总结一本书/一段代码，不要指望它「凭空回忆」（参数），直接把内容粘贴进对话框（上下文），效果显著更好。

### 5.2 模型需要 token 来思考

模型生成每个 token 时的「计算量」有限。问「23 个苹果加 17 个橘子乘以 5 等于多少，直接给答案」它很容易算错——**步骤不够**。

> **应用技巧**：让模型 **step by step** 回答；复杂计算引导它用**代码解释器**——写代码其实是把计算「外包」给 Python，而不是在「脑子里」硬算，准确率最高。

### 5.3 幻觉是必然的

模型是概率预测机器，本质是在「做梦」，只是大多数时候梦境与现实重合。**不要完全信任它**——尤其对训练数据中少见的内容。把它当**初稿生成器**，而不是真理来源。

### 5.4 其它要点

- **自我认知**：LLM 没有真正的自我意识，「你是谁？」的回答只是训练数据的统计最佳猜测，靠**系统提示**预设一致的人格（描述自己、能力与限制）。
- **上下文学习（in-context learning）**：在提示里给几个示例，就能引导基础模型的行为——不更新参数，只换上下文。

---

## 6. 总结：像「瑞士奶酪」的 LLM

现在的 LLM 像一块瑞士奶酪：
- **预训练**给了它广博（但模糊）的知识；
- **SFT** 让它学会像人一样对话；
- **RL** 正在让它学会「慢思考」解决难题；
- 但在「数草莓里的 r」这种任务上又弱得好笑。

把它当趁手的工具，用好它，同时**保持独立思考和验证的习惯**。
